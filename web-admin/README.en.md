# ZiMiaoYuan · Web Admin Console

[English](README.en.md) · [中文](README.md)

A standalone web console sharing the same cloud development database as the mini program, used in the browser to manage cat review, edit proposals, record review, cat content editing, record management, user management, sponsorship management, sub-admin management, and the data dashboard.

- Frontend: Vue3 + Vite + Element Plus + vue-router (hash routing)
- Auth: account password + token (independent of the mini program user system, see below)
- Deployment: CloudBase static hosting

## Why a New Auth Method

Mini program cloud functions determine admins via `cloud.getWXContext().OPENID`, but a browser has no WeChat context and cannot obtain an openid. So the console adds token auth: admin accounts live in a separate `admins` collection, a token is returned after login, and the web console attaches the token to every cloud function call.

## Deployment Steps

### 1. Deploy Cloud Functions

In WeChat DevTools, upload and deploy **all** cloud functions under `cloudfunctions/` one by one ("Upload and deploy (install dependencies in cloud)") — 32 in total, full list in the root `cloudbaserc.json`.

> Cloud functions used by the web console have added `requireAdmin` dual-channel auth: the web uses token, the mini program uses openid; the mini program's existing admin features are unaffected.

### 2. Set Environment Variable + Initialize Admin

1. In the CloudBase console, configure the `ADMIN_INIT_KEY` environment variable for the `initAdmin` cloud function with a random string (e.g. generated by `openssl rand -hex 16`).
2. In the CloudBase console, go to "Cloud functions → initAdmin → cloud test" and invoke it once:

```json
{
  "initKey": "the ADMIN_INIT_KEY you set above",
  "username": "admin",
  "password": "your strong password"
}
```

Returning `code: 0` means creation succeeded. `initAdmin` only works when the `admins` collection is empty and creates the **super admin** (`role: super`). Afterwards, adding admins, changing roles, resetting passwords, and deleting are all done on the console's "Sub-admin management" page — no code changes needed.

### 3. Build the Frontend

```bash
cd web-admin
npm install
npm run build
```

The output is in the `dist/` directory.

### 4. Deploy to CloudBase Static Hosting

Using the CloudBase CLI:

```bash
npm install -g @cloudbase/cli
tcb login
tcb hosting deploy dist -e cloud2-d1gbjipxm9c21dd8d
```

After deployment, open the default domain shown in the console (e.g. `https://cloud2-d1gbjipxm9c21dd8d-xxx.tcloudbaseapp.com/`) to access the console.

## Local Development

```bash
cd web-admin
npm install
npm run dev
```

Open `http://localhost:5173` in the browser. Local development also uses the real cloud environment (anonymous login + cloud functions), so complete the cloud function deployment and admin initialization above first.

> The `ENV_ID` in `src/api.ts` must match your environment; it is currently `cloud2-d1gbjipxm9c21dd8d`.

## Security Notes

- Admins are split into two tiers: `super` (super admin) and `admin` (sub-admin). Only the super admin can enter the "Sub-admin management" page to add/remove admins, change roles, and reset passwords; sub-admins can use the rest of the console normally.
- Passwords are hashed with Node's built-in `crypto.scryptSync` with salt, stored as `salt:hash`, with no extra dependencies.
- Tokens are generated with `crypto.randomBytes(32)`, valid for 7 days, stored in the `adminTokens` collection; `requireAdmin` rejects expired tokens.
- It is recommended to bind HTTPS to the static hosting domain (CloudBase provides it by default), and never expose `ADMIN_INIT_KEY` in production.
- The web console's anonymous login uses the CloudBase web SDK only to gain permission to call cloud functions; the real console auth relies on the token, and the anonymous identity itself has no admin privileges.
